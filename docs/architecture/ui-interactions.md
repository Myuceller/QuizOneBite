# UI 인터랙션 기준

사용자가 누르고 선택한 결과를 바로 알아볼 수 있도록 짧은 반응을 제공한다. 버튼·링크·주제·난이도·보기·입력 폼·풀이 결과에서 같은 원칙을 적용한다. 별도 애니메이션 라이브러리 없이 CSS와 기존 React 상태로 구현한다.

## 동작별 규칙

- 버튼과 선택 카드는 6px 아래 테두리로 높이를 표현하고 누르는 동안 6px 내려가며 조금 작아진다. 놓으면 짧은 스프링 전환으로 돌아온다. 선택 카드는 3px 눌린 상태와 체크·색을 유지한다. hover는 정밀 포인터 환경을 우선하고 터치에서는 누름·선택 상태로 충분히 구별한다. 비활성화된 컨트롤은 움직이지 않는다.
- 선택은 색만으로 표현하지 않는다. 체크 표시·테두리·문구와 네이티브 radio/`aria-pressed`를 유지한다. 키보드 방향키·Tab·Space와 focus 표시를 훼손하지 않는다.
- 주제 아이콘과 체크는 선택 시 튀어나오고, 카드 외곽에 짧은 파동이 퍼진다. 주제별 색이 선택 카드·난이도·설정 요약에 연결되며 난이도 막대는 아래에서 채워진다. 설정 요약은 값이 달라질 때만 짧게 전환한다.
- 네트워크 대기는 점 애니메이션, 실제 대기 문구, 비활성화 상태로 표시한다. 애니메이션 종료를 기다리느라 요청이나 이동을 지연시키지 않는다. 연속 클릭으로 중복 요청이 생기지 않게 한다.
- 정답·오답 효과는 서버 채점 응답 뒤에만 실행한다. 정답에는 짧은 색 변화와 축하 효과, 오답에는 작은 흔들림과 배울 내용을 제시한다. 출제 전 정답 정보를 클라이언트로 전달하지 않는다.
- 문제 전환은 240ms 안팎, 누르는 반응은 60~70ms, 복귀는 240ms 안팎을 기본으로 한다. 결과 점수 링은 750ms, 정답·풀이 완료 색종이는 950ms에 최대 175ms 시차를 두어 한 번 재생한다. 대기 표시 외 장식의 무한 반복은 피한다.
- 홈의 장식용 퀴즈 카드 묶음은 진입 시 나타나고 마우스를 올리면 펼쳐진다. 버튼의 반짝임도 hover·키보드 focus 시 한 번만 재생한다. 장식은 클릭 가능한 기능처럼 탭 순서에 넣지 않으며, 모바일에서는 크기를 줄여 본문과 겹치지 않도록 배치한다.
- 결과 화면의 문제 목록은 짧은 간격으로 나타나며 즉시 클릭 가능하다. 현재 질문과 정답·오답 상태는 진행 표시의 숫자·기호·접근성 텍스트로 구분한다.
- 화면 진입은 Next.js template의 짧은 페이드로 처리한다. 전역 템플릿의 하위 Client Component는 해당 세그먼트 이동 시 재생성된다는 점을 고려한다. 진행 중 풀이의 실제 상태는 서버 저장본에서 복원한다.

## 접근성과 구현 위치

홈 출제 설정은 주제·난이도·모드 사이에 데스크톱 40px, 모바일 32px 여백을 둔다. 제목과 선택 카드 사이에는 24px(모바일 20px), 카드 행 사이에는 24px(모바일 22px)를 확보해 그림자·선택 이동·키보드 초점 테두리가 다음 영역과 붙지 않게 한다.

OS의 `prefers-reduced-motion: reduce`에서는 CSS Modules를 포함한 애니메이션·전환을 끈다. 정적인 색·체크·점수·로딩 문구는 남는다. 장식은 `aria-hidden`, 저장 결과는 `role="status"`, 오류는 `role="alert"`를 사용한다. 점수나 축하 모션을 읽기 순서의 필수 단계로 만들지 않는다.

공통 효과는 `src/app/interactions.css`, 주제·난이도와 문제 제출의 효과는 해당 CSS Module, 대기 장식은 `src/components/busy-indicator.tsx`, 색종이는 `src/components/celebration.tsx`에 있다. 실제 선택·요청 상태는 각 기능 컴포넌트에 유지한다. 공통 스타일을 추가할 때 비활성 상태·모션 감소·hover/active 선택자 우선순위를 함께 확인한다.

검증은 lint·typecheck·기존 테스트·프로덕션 빌드와 로컬 HTTP 확인을 기본으로 한다. 브라우저 검증이 허용되는 환경에서는 390px 모바일/데스크톱, 키보드 선택·초점 이동, 느린 요청·실패·연속 클릭, 정답·오답·다시 보기, 모션 감소 설정까지 실제 조작한다. 브라우저를 검사하지 않았다면 시각적 검증 완료로 보고하지 않는다.
