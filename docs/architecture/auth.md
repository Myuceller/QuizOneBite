# 인증

Better Auth + PostgreSQL 이메일·비밀번호 인증을 사용한다. 직접 암호화나 세션 프로토콜을 구현하지 않는다. 비밀번호는 라이브러리가 해시하고 세션은 DB에 보관한다. 공식 자료: [Next.js 통합](https://better-auth.com/docs/integrations/next), [DB 스키마](https://better-auth.com/docs/concepts/database), [요청 제한](https://better-auth.com/docs/concepts/rate-limit).

## 현재 동작

- 회원가입: 닉네임 2~24자, 이메일, 비밀번호 8~128자. 성공 후 자동 로그인하여 `/welcome`으로 이동한다.
- 로그인: 이메일·비밀번호 인증 후 홈으로 이동한다.
- 로그아웃: 서버 세션 폐기와 쿠키 제거가 성공해야 로그인 화면으로 이동한다.
- 세션: 7일 만료, 하루 단위 갱신. HttpOnly·SameSite=Lax 쿠키, HTTPS에서는 Secure를 사용한다. 쿠키 캐시를 켜지 않아 DB 폐기를 즉시 반영한다.
- 서버에서 환영 화면·기록 페이지를 보호한다. 다른 사용자의 기록 URL은 404로 응답한다.
- 인증 요청 제한: DB 공유 저장소, 로그인 분당 5회·회원가입 분당 3회. 개발·테스트에서도 CSRF와 Origin 검사를 켠다.

## 환경변수

`npm run db:env`는 기존 값을 보존하며 `BETTER_AUTH_SECRET`과 `BETTER_AUTH_URL`을 `.env.local`에 추가한다. 비밀값은 32바이트 무작위 값이다. 환경변수에는 실제 서비스의 정확한 origin을 넣어야 한다. 기본 개발 URL은 `http://127.0.0.1:3000`, Docker URL은 `http://127.0.0.1:3001`이다. 다른 호스트로 접속하려면 해당 URL 설정도 함께 변경한다.

운영 비밀값은 로컬과 별도로 생성해 배포 플랫폼의 secret 저장소로 주입한다. loopback 외에는 HTTPS URL만 허용한다. 쿠키에 인증정보를 담으므로 배포 프록시는 클라이언트의 전달 IP 헤더를 제거하고 신뢰할 수 있는 값을 다시 설정해야 한다. 프록시 외의 경로로 원본 서버에 접속하지 못하게 하고 선택한 호스팅에 맞게 IP 전달 설정을 검증한다.

## 후속 작업

이메일 소유 확인과 비밀번호 재설정 메일 발송은 아직 구현하지 않았다. 현재 가입된 이메일은 `emailVerified=false`이며 소유권이 확인된 주소로 취급하면 안 된다. 공개 회원 모집 전에 메일 공급자·도메인을 연결하고 이메일 인증과 복구를 구현한다. 소셜 로그인, 계정 삭제·내보내기, 운영 약관·개인정보 처리 안내도 후속 출시 작업이다.

실제 계정 복구 기능이 없는 상태이므로 이번 단계의 계정은 로컬 테스트용이다. 운영 사용자 계정을 임의로 초기화하거나 비밀번호를 로그에 출력하지 않는다.
