# AI 연결 규칙

## 구성

AI 연결은 서버에서만 실행하며, 퀴즈 기능은 `QuizGenerator` 계약을 통해 생성기를 사용한다. OpenAI SDK와 API 키를 React 클라이언트 컴포넌트에 전달하지 않는다.

| 환경변수 | 기본 설정 | 역할 |
| --- | --- | --- |
| `AI_PROVIDER` | `mock` | `mock` 또는 `openai` 생성기 선택 |
| `OPENAI_MODEL` | `gpt-6-astra` | 사용할 OpenAI 모델 ID |
| `OPENAI_API_KEY` | 비어 있음 | `openai` 제공자를 사용할 때 필요한 서버 비밀값 |

환경변수는 서버에서 실제로 필요할 때 읽고 검증한다. Mock 모드는 API 키를 요구하지 않는다. 실제 API 요청을 실행하는 확인 작업은 비용이 발생하므로 자동 테스트와 빌드에 포함하지 않는다. 키는 `.env.local` 등 로컬 환경에 두고 Git에 커밋하지 않는다. 비밀값에 `NEXT_PUBLIC_` 접두사를 사용하지 않는다.

OpenAI 어댑터는 Responses API와 Zod 기반 Structured Outputs를 사용하며, Astra의 reasoning effort는 `low`를 기본으로 한다. 모델 변경은 환경설정으로 가능하지만 지원 기능과 출력 품질을 확인한 뒤 적용한다. [Astra 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra), [Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs).

## 생성 계약

- 입력: `general`, `science`, `history`, `geography`, `culture` 카테고리와 `easy`, `medium`, `hard` 난이도.
- 문제 수: 기본 3개, 최대 5개. 서버에서 입력을 검증한다.
- 출력: 문제, 선택지, 정답 인덱스, 해설을 포함한 구조화된 초안.
- 상태: 생성 직후에는 `unreviewed`. 모델이 만든 내용을 검토 완료로 표시하지 않는다.
- 공개 미리보기: 정답 인덱스와 해설을 제거한 응답만 전달한다.

스키마 검증은 필수 필드, 타입, 값의 범위를 확인한다. 정답의 사실성, 문제의 모호함, 출처의 신뢰성까지 보장하지 않는다. AI가 출력한 정답을 그대로 운영용 정답으로 확정하지 않는다.

운영자 문제 은행 생성은 위 공통 입력에 소분류 ID를 필수로 추가한 `BankGenerationInput` / `BankGenerator` 계약을 사용한다. 분류 검증과 저장 규칙은 [운영자 생성 가이드](generation.md)를 따른다.

## 프롬프트 변경

프롬프트에는 명시적인 버전을 두고, 문제 생성 지침과 출력 스키마의 변경을 함께 검토한다. 변경 시에는 고정된 카테고리·난이도 사례로 출력 형식, 선택지의 구분, 정답의 유일성, 해설의 정확성을 확인한다. 자동 테스트에서는 Mock을 사용하고, 실제 모델 평가 결과는 별도로 기록한다.

현재 PostgreSQL에는 생성 당시의 제공자, 모델 ID, 프롬프트 버전, 저장 시각, 검토 상태를 문제와 함께 저장한다. 별도 문제 은행은 운영 CLI로 초안을 가져와 출처 검토 후 게시한다. 게시된 문제의 수정은 기존 문제를 퇴역시키고 새 ID로 등록하며 기존 풀이 스냅샷은 보존한다. 운영자 전용 `bank:generate`가 참고 자료 기반 초안을 문제 은행에 직접 저장하며, 검토·게시 명령과 연결된다. 미리보기 응답은 저장 성공 이후에만 반환한다.

## 운영 연결 전 필요한 작업

현재 `POST /api/quiz/preview`는 개발용 AI 미리보기와 로그인 사용자용 Mock 미리보기를 제공한다. 운영 환경의 유료 AI 호출은 여전히 차단한다. 운영 환경에서 AI 생성을 제공하려면 다음을 먼저 구현한다.

1. 구현된 인증·소유권·분당 요청 제한에 더해, AI 호출에 맞는 일별 비용 한도와 이메일 인증 정책을 확정한다.
2. 요청 시간·출력량·사용량 제한 및 비용 관측. 재시도는 상한을 두고 설계한다.
3. 구현된 DB 문제 은행·검토 절차에 AI 생성 초안 가져오기를 연결한다. 검토 완료 문제만 퀴즈에 사용한다.
4. 구현된 서버 세션·채점 경계를 유지한다. 답안을 제출하기 전에 클라이언트로 정답을 보내지 않는다.
5. 비밀값이나 불필요한 사용자 정보를 남기지 않는 오류 및 생성 이력 기록.

개발 중에도 모델의 거절, 형식 오류, 서비스 장애를 정상적인 실패 경로로 처리한다. 사용자가 서버의 API 키나 원문 오류 내용을 볼 수 있게 응답하지 않는다.

## 비용을 쓰지 않는 플레이 경로

`/api/play`와 평가·신고 API는 PostgreSQL만 사용하며 AI 어댑터를 호출하지 않는다. 초기 문제 10개와 운영 CLI는 [문제 은행 문서](../quiz/bank.md)에 정리했다. 운영자 전용 소량 생성과 DB 월 예산 예약·사용량 기록을 구현했다. 기본 예산 0으로 잠겨 있으며 실제 호출은 키·예산·실행 옵션을 설정해야 한다. 설정과 검수 흐름은 [AI 생성 가이드](generation.md)를 참고한다. Batch API와 자동 스케줄은 아직 없다.
