# Docker 실행과 출시 계획

## 현재 확인할 수 있는 버전

샘플 문제와 회원가입·로그인·로그아웃·환영 화면·내 문제 모음을 제공한다. 아직 정답 제출·채점이 없는 미리보기 버전이다. 공개 배포나 앱스토어 출시는 수행하지 않았다.

```sh
npm run db:env
npm run docker:up
```

접속: <http://127.0.0.1:3001>. `npm run docker:logs`로 앱 로그를 보고 `npm run docker:down`으로 컨테이너를 내린다. DB 볼륨은 유지된다. 최초 실행에는 Node 이미지와 패키지 다운로드가 필요하다.

## 구성

| 서비스 | 역할 |
| --- | --- |
| db | PostgreSQL 18, 영속 볼륨, 준비 상태 확인 |
| migrate | 현재 SQL 마이그레이션을 한 번 적용하고 종료 |
| app | Next.js 프로덕션 서버, 3001 → 컨테이너 3000 |

앱은 DB 준비 및 마이그레이션 성공 후 시작한다. 이미지 내부에서 root 대신 `node` 사용자로 실행한다. `/api/health`는 앱 응답, `/api/health/ready`는 DB와 계정·퀴즈 핵심 스키마를 확인한다. Next.js standalone 출력으로 실행 의존성만 복사한다. `.dockerignore`로 `.env*`, 개발 설정, Git, 로컬 빌드 결과를 제외하며 비밀값은 실행 시에만 전달한다.

로컬 Compose는 외부에 포트를 공개하지 않고 127.0.0.1에만 바인딩한다. 두 웹 서버(개발 3000·Docker 3001)가 같은 DB를 사용하므로 계정과 기록을 공유한다. Compose DB 비밀번호는 `db:env`가 생성한 URL에 안전한 hex 값 기준이다. 특수문자 비밀번호를 임의로 넣을 때는 접속 URL을 별도로 인코딩해야 한다.

공식 참고: [Next.js Docker 배포](https://nextjs.org/docs/app/getting-started/deploying#docker), [Docker Compose 시작 순서](https://docs.docker.com/compose/how-tos/startup-order/).

## 공개 웹 출시 순서

1. **핵심 게임:** 답 선택·서버 채점·결과·해설·재도전, 저장된 플레이 기록.
2. **운영 계정:** 이메일 인증·비밀번호 재설정, 계정 삭제, 서비스 운영자 정보와 개인정보 처리 안내.
3. **문제 품질:** 샘플 또는 검토 완료 문제 은행으로 공개하고, Astra 생성은 검토·비용 한도·실패 관측을 갖춘 뒤 확장한다.
4. **배포 환경:** 사용자가 선택한 Docker 지원 호스팅·운영 PostgreSQL·도메인·HTTPS를 연결한다. 서버 비밀값, DB 백업과 복구, 제한된 런타임 DB 계정, 로그·알림을 설정한다.
5. **출시 검증:** 모바일 화면·접근성, 가입부터 채점까지 전체 흐름, 운영 DB 마이그레이션·복구 절차를 확인하고 공개한다.

이번에는 유료 호스팅 가입이나 공개 배포를 실행하지 않았다. 호스팅 결정 전에도 이 Docker 이미지로 운영 모드 동작을 로컬에서 확인할 수 있다. 앱스토어용 네이티브 패키징 여부는 웹 출시 후 별도로 결정한다.

## 검증

`npm run check`: 린트·타입·단위 테스트·프로덕션 빌드. `npm run test:db`: 임시 DB를 만들어 인증, 로그아웃, CSRF, 소유권, 동시 요청 제한과 저장 트랜잭션을 확인하고 해당 DB만 제거한다. 테스트는 유료 AI 호출과 메일 발송을 하지 않는다.
