# 문제 은행과 사용자 평가

2026-10-15 신규 2,600개 게시 이후 Render 테스트 DB의 게시 문제는 **2,948개**다. 로컬은 게시 348개와 신규 초안 2,600개를 유지한다. [원격 게시 기록](../records/2026/2026-10-15-draft-remote-sync.md)을 참고한다. 아래 초기 생성·추가 이력의 수량은 해당 시점 기준이다.

## 이번 구현

홈에서 로그인 후 **5문제 한 입** 또는 **무한모드**를 선택하고, 서버 채점·해설·출처를 확인한 뒤 문제를 평가한다. 무한모드는 한 문제씩 계속 출제하고 사용자가 종료한다. `/play/history`에서 최근 30회 풀이를 이어 하거나 다시 볼 수 있다. 기존 생성 미리보기는 `/preview`, 기존 문제 모음은 `/history`에 유지한다. 플레이·평가·채점은 AI를 호출하지 않는다.

초기 마이그레이션은 공식 자료(NASA, NIST, NOAA, UNESCO)를 대조한 10개 예제를 게시한다. 정답·해설 옆에 출처를 표시한다. 난이도는 초기 편집값이며 정답률로 자동 보정하지 않는다. 이후 운영자 생성으로 대표 6개와 전체 출제 조건용 45개를 로컬에 추가했다. [생성·검수·비용 기록](../ai/generation.md)에 상세히 정리했으며, 새 배포 DB에 이 로컬 문항이 자동 복사되지는 않는다.

확정한 대분류·소분류와 현재 적용 범위는 [문제 분류 v1](taxonomy.md)에 정리했다.

## 출제 정책

1. `published` 문제 중 선택한 주제·난이도에 맞는 후보를 찾는다.
2. 해당 사용자에게 노출되지 않은 문제 → 마지막 노출이 7일 이상 지난 문제 → 최근 문제 순서로 채운다. 풀지 않고 이탈해도 노출로 기록한다.
3. 같은 우선순위 안에서는 이번 게임에 덜 등장한 주제·난이도를 우선한다.
4. 후보의 평가 수 합계가 20 미만이면 균등 무작위로 선택한다.
5. 평가가 쌓이면 매 추첨마다 인기 60% / 평가 부족 30% / 기타 10% 확률로 풀을 선택한다. 선택한 풀이 비어 있으면 현재 후보 전체로 대체한다.

인기 문제의 조건은 평가 5개 이상이며 `(추천 수 + 3) / (전체 평가 수 + 6)`이 0.6 이상인 것이다. 초기 6표의 중립 사전값이 1명 중 1명 추천을 과대평가하지 않도록 한다. 평가 부족은 5표 미만, 기타는 나머지다. 비율은 장기적인 목표이며 매 5문제마다 고정 비율을 보장하지 않는다. 최근 노출 회피와 주제 균형이 인기보다 우선한다.

5문제 모드에서는 한 게임 안에 중복 문제를 내지 않는다. 후보가 적으면 가능한 수만 내고, 이미 본 문제에는 복습 표시를 붙인다. 보기 순서는 서버에서 섞고 정답 위치도 함께 보관한다. 생성할 때 ‘위의 모든 보기’처럼 순서에 의존하는 선택지를 피해야 한다.

### 무한모드

- 시작 시 한 문제를 저장한다. 답을 확인한 뒤 `다음 문제`를 누르면 같은 세션에 한 문제를 추가한다. 매번 현재 게시 상태와 처음 선택한 주제·난이도를 적용하며 AI를 호출하지 않는다.
- 현재 세션에서 가장 적게 등장한 문항을 우선한다. 따라서 가능한 문항을 한 번씩 만나기 전에는 반복하지 않고, 모두 만난 뒤에는 복습으로 계속한다. 가능한 경우 바로 직전 문제의 연속 반복도 피한다. 후보가 하나뿐이면 그 문제를 다시 낼 수 있다.
- 다음 문제 요청은 마지막 문제의 위치를 포함한다. 사용자별 선택 잠금과 세션 잠금으로 동시 요청을 직렬화하고, 같은 위치의 재요청은 이미 저장된 다음 문제를 반환한다. 답을 제출하지 않고 건너뛸 수 없다.
- `여기까지 마치기`는 제출한 답까지 집계해 종료한다. 아직 풀지 않은 문제는 점수·결과 목록에서 제외한다. 종료 후 새 문제 추가와 미제출 답안 제출은 차단하며, 종료 재요청은 같은 결과를 반환한다.
- 브라우저를 닫거나 새로고침해도 저장된 문제와 누적 점수는 유지된다. 기록 화면에서 이어 풀 수 있다. API와 해설 목록은 최근 20문제까지만 반환하고 누적 풀이 수·정답 수는 전체 기록으로 계산한다.
- 현재 게시 후보가 모두 없어지면 안내를 표시하고, 다시 시도하거나 종료할 수 있다. 오류로 기존 풀이가 삭제되거나 임의로 완료되지 않는다.

## 데이터와 안전한 채점

| 테이블 | 역할 |
| --- | --- |
| `bank_questions` | 게시 가능한 문제, 정답·해설·출처·생성 이력·검수 상태 |
| `play_sessions` | 사용자별 게임과 모드, 완료 시각, 시작 요청 ID |
| `play_items` | 출제 당시 문항·섞인 보기·정답의 스냅샷과 제출 답안 |
| `question_ratings` | 문제·사용자당 한 표, 아쉬운 이유 |
| `question_reports` | 문제·사용자당 한 오류 신고, 처리 상태 |
| `play_limits` | 서버 인스턴스가 공유하는 사용자·행동별 요청 제한 |

초안 생성 기록(`quizzes`, `quiz_questions`)과 게시 문제 은행을 분리한다. 문제 은행의 상태는 `draft → published → paused/retired`다. 게시에는 출처와 검수 기록이 필요하다. 공개된 내용의 수정은 기존 문제를 retired로 만들고 새 ID로 가져온다. 과거 플레이의 스냅샷과 평가는 원래 버전에 남는다.

답을 제출하지 않은 문항의 정답·해설·출처는 API와 페이지 초기 데이터에서 제외한다. 서버는 소유자와 문제 순서를 확인한다. 같은 답의 재제출은 같은 결과를 반환하고, 제출한 답 변경은 거부한다. 한 게임의 동시 제출은 DB 잠금으로 직렬화한다. 문제를 일시 중지해도 이미 출제된 게임은 당시 스냅샷으로 마칠 수 있다.

시작 요청 ID를 재사용하면 중복 게임을 생성하지 않는다. 사용자별 동시 시작도 직렬화한다. 변경 API는 로그인과 설정된 origin의 JSON 요청을 요구하며, 새 게임은 분당 10회, 답안·피드백은 각각 분당 60회, 무한모드 다음 문제·종료는 합산 분당 60회 제한한다. 개인 기록 응답은 `no-store`다.

## 평가·신고

- 직접 답을 제출한 문제에만 평가·신고할 수 있다. 채점 성공 여부와 무관하다.
- 추천/아쉬움은 계정당 한 표로 UPSERT하며 수정할 수 있다. 아쉬움 이유는 뻔함·모호함·보기 품질이다.
- 사실 오류 신고는 별도다. 한 계정의 반복 신고로 수가 늘지 않는다.
- 열린 신고가 서로 다른 3개 계정에서 들어오면 새 출제를 중지(`paused`)한다. 1~2건 신고도 검수 목록에 나타난다.
- 재검수 후 문제가 맞다면 publish 명령으로 다시 게시하면서 열린 신고를 해결 처리한다. 수정이 필요하면 기존 문항을 은퇴시키고 새 버전으로 등록한다.

이는 계정 단위 중복 방지이며 다중 계정 조작을 완전히 방지하지 않는다. 이메일 인증·계정 신뢰도·관리자 검수 UI는 후속 과제다. 정답률을 인기 점수로 사용하지 않는다.

## 운영자 도구

공개 웹에서 문제를 게시하는 API는 만들지 않았다. DB 접근 권한을 가진 운영자가 CLI를 실행한다. 기본 명령은 `.env.local`을 읽는다. 원격 DB에서는 제공업체의 연결 안내에 따라 대상 `DATABASE_URL`을 명시적으로 설정해야 한다. Render 무료 DB의 외부 접속은 기본 차단되어 있으므로, 원격 관리가 필요할 때만 운영자 IP와 TLS 연결을 설정하고 작업 후 접근을 회수한다.

```sh
npm run bank -- import /private/path/questions.json
npm run bank -- queue
npm run bank -- show <문제UUID>
npm run bank -- publish <문제UUID> <검수자> "정답과 해설을 출처에서 확인함"
npm run bank -- pause <문제UUID> <검수자> "오류 재검토"
npm run bank -- retire <문제UUID> <검수자> "수정 버전으로 교체"
npm run bank -- export /private/path/question-bank.json
```

import는 항상 초안으로 저장한다. 기존 draft ID만 수정할 수 있으며 내용 중복을 차단한다. 파일 전체를 트랜잭션으로 처리하므로 중간 실패 시 모두 롤백한다. export에는 정답이 들어 있으므로 공개 디렉터리나 Git에 두지 않는다. export는 문항 콘텐츠 이동용이며 사용자 기록·평가·검수 이력을 포함하는 DB 전체 백업을 대신하지 않는다. 가져온 export도 다시 검수해야 게시된다.

JSON 형식(배열, 최대 1,000문제):

```json
[
  {
    "category": "science",
    "difficulty": "medium",
    "question": "문제 문장",
    "options": ["보기 A", "보기 B", "보기 C", "보기 D"],
    "correctAnswerIndex": 0,
    "explanation": "정답 해설",
    "sources": [{ "title": "확인한 자료 제목", "url": "https://example.com/source" }],
    "provenance": { "provider": "openai", "model": "gpt-6-astra", "promptVersion": "직접 기록한 생성 버전" }
  }
]
```

`id`를 생략하면 새 UUID가 발급된다. 출처는 HTTPS만 허용하며, 출처 링크가 있다는 사실만으로 정확성이 보장되지는 않는다. 게시 명령은 운영자의 실제 내용 검토를 전제로 한다. 운영자용 `npm run bank:generate`는 참고 자료로부터 소량의 초안을 직접 저장하고, DB 기반 월 예산 예약·사용량 기록을 적용한다. [설정과 실행 순서](../ai/generation.md)를 참고한다. 공개 웹의 유료 생성은 계속 차단하며 자동 Batch 제출은 아직 없다.

## 검증

단위 테스트는 점수 보정·새 문제 우선·60/30/10 선택·보기 정답 매핑과 API 인증·origin·입력·오류 경계를 검사한다. PostgreSQL 통합 테스트는 실제 마이그레이션, 비공개 정답, 소유권, 동시 시작/제출, 한 표 수정, 신고 임계치, 출제 제외, 검수 CLI와 요청 제한을 검사한다.

## 상식성 검수

문제 생성·게시에는 [상식 품질 기준](quality.md)을 적용한다. 2026-10-06 재검수에서 기존 문항 25개를 중단한 뒤, 부족분을 추가 생성·검수해 당시 로컬과 Render staging 모두 게시 76개·중단 25개였다. 당시 5개 분야 × 3난이도마다 최소 5개를 확보했다. 과거 생성 수는 당시 기록이며 자세한 비용·검증 결과는 [생성 기록](../ai/generation.md#분야난이도별-최소-5개-확보-2026-10-06), 원격 반영은 [배포 기록](../operations/render.md#문제-은행-첫-원격-반영-2026-10-06)을 참고한다. 소분류는 생성과 내부 메타데이터에 적용하며 현재 플레이 필터는 5개 주제를 유지한다.

2026-10-07에는 API 생성 11개와 별도 API 없이 직접 작성한 177개를 로컬에 추가했다. 당시 로컬 게시 264개·중단 25개였으며, 49개 소분류마다 기존 문제를 포함해 최소 5개를 확보했다. 상세 수량·검수·검증은 [소분류 보강 기록](../records/2026/2026-10-07-question-generation.md)을 따른다. 직접 작성 문항은 `codex-editorial` 이력으로 구분하고 기존 초안 가져오기·검수·게시 절차를 사용한다.

2026-10-08에는 짧은 보기 기준으로 5개 플레이 주제에 5개씩 총 25개를 추가해 당시 게시 289개·중단 25개가 되었다. 해당 검수·저장·플레이 검증과 비용은 [짧은 보기 문제 추가 기록](../records/2026/2026-10-08-short-options-questions.md)을 참고한다.

같은 날 후속 요청으로 주제마다 쉬움·보통·어려움 5개씩, 총 75개를 더 추가했다. 당시 로컬은 **게시 364개·중단 25개**였고 49개 소분류별 최소 5개와 5개 분야 × 3난이도별 최소 5개를 확보했다. 새 보기 300개는 모두 1~3어절·최대 10자이며 별도 API 비용은 없었다. 해당 수량과 15개 출제 필터 검증은 [75개 추가 기록](../records/2026/2026-10-08-balanced-75-questions.md)을 따른다. 2026-10-07~08 추가분은 당시에는 로컬 전용이었으며, 2026-10-12에 QA 후 원격 반영과 단답 개정을 진행했다.

## 오답 복습·북마크·성적·오늘의 5문제

홈의 학습 카드와 `/play/learning`에서 오답 복습, 북마크 모아 풀기, 분야별 성적, 오늘의 5문제를 이용한다. 풀이 기록과 결과에서도 복습으로 이동할 수 있다.

- **오답**: 계정별·문제별 가장 최근에 제출한 답이 오답인 문제를 모은다. 다시 맞히면 목록에서 빠지고 다시 틀리면 재등록된다. 답을 제출하지 않은 세션은 이 판단에 영향을 주지 않는다. 같은 문제를 여러 번 틀려도 목록에는 한 번 나온다.
- **북마크**: 본인이 답을 제출한 문제에 저장·해제 버튼이 나타난다. 계정·문제당 한 건을 저장하며 반복 저장·해제 요청은 안전하게 처리한다. 목록에서 개별 재도전하거나 모아서 최대 5문제를 풀 수 있다.
- **복습 출제**: `/api/play`의 `source: wrong | bookmarks`를 사용한다. `questionId`는 이 두 출처에서만 지정할 수 있으며 반드시 본인 목록에 속해야 한다. 현재 게시된 문제만 새 세션으로 출제하며 정답·해설은 다시 답을 제출한 뒤 공개한다. 중지된 문제는 목록에 검토 중으로 남고 출제 수에서 제외한다. 목록은 20개씩 페이지를 나눈다.
- **분야별 성적**: 본인이 제출한 모든 답의 풀이 수·정답 수·정답률을 5개 출제 분야별로 표시한다. 복습과 무한모드의 반복 풀이를 포함한다. 제출 재시도는 중복 집계하지 않는다. 문제의 출제 시점 분야를 `play_items.category`에 보관한다. 기존 기록은 마이그레이션 시 은행의 분야로 채운다.
- **오늘의 5문제**: 한국 시간(`Asia/Seoul`) 날짜별로 처음 요청할 때 게시된 문제 중 5개를 골라 공통 스냅샷을 저장한다. 생성은 DB 잠금으로 직렬화하며 모든 계정이 같은 문제·순서를 만난다. 보기 순서는 각 풀이에서 섞는다. `source: daily`는 주제·난이도를 전체, 문제 수를 5, 모드를 일반 모드로 고정한다. 계정당 날짜별 세션은 하나이며 재요청은 진행 중인 풀이 또는 완료 결과를 반환한다. 전날의 미완료 풀이는 기록에서 계속할 수 있다. 최근 30일의 참여·완료 기록을 제공한다.
- **오늘의 문제 검토**: 공통 묶음에 중지된 문제가 생기면 새로운 참여를 잠시 막는다. 기존에 시작한 풀이는 기존 스냅샷으로 유지한다. 첫 생성 때 게시 문제가 5개 미만이면 빈 묶음을 저장하지 않고 준비 중으로 응답한다.

`0009_learning_features.sql`이 북마크·공통 일일 묶음과 세션 출처·분야 스냅샷을 추가한다. 공개 쓰기 요청은 기존 인증·동일 출처·공유 요청 제한을 사용한다. 북마크 API는 `POST /api/questions/[id]/bookmark`의 `{ saved: boolean }`이며, 조회와 집계는 모두 서버 세션의 사용자 ID로 제한한다. 이 기능들은 AI를 호출하지 않는다.

## 이미지형 문항

국기·지도·작품·기호·도표처럼 시각 정보를 읽는 문항은 `image: {src, alt, width, height}`를 저장한다. 이미지 없는 문항은 생략하거나 `null`을 사용한다. `src`는 `/quiz-images/<SHA-256 앞 32자리>.svg` 또는 `.webp` 형식의 자체 호스팅 파일만 허용한다. SVG는 실행 코드·외부 참조·메타데이터를 제거하고, WebP는 정적인 이미지로 변환하며 EXIF·XMP 등 메타데이터를 제거한다. 파일명은 실제 바이트의 해시로 고정한다. 운영 CLI는 import와 publish 때 해당 파일의 존재를 확인하고 export에도 이미지 정보를 보존한다. 외부 이미지 URL은 허용하지 않는다.

파일명·대체 설명에 정답 국가명을 넣지 않는다. 대체 설명은 시각적 특징만 설명하며 사용자가 펼쳐 읽을 수 있다. 이미지 로딩 실패 시 같은 설명을 바로 표시한다. 원래 비율을 유지하며 풀이·북마크/오답 목록·결과 썸네일에 표시한다. Docker 런타임에도 `public` 폴더를 복사한다.

이미지 정보는 출제 시 `play_items`와 일일 문제의 `daily_items`에 복사하므로 이미 시작한 풀이와 당일 확정된 문제는 바뀌지 않는다. 게시 문항을 이미지형으로 바꿀 때는 기존 ID를 중지하고 검수한 새 ID를 게시한다. 중복 제약은 정규화한 질문과 이미지 경로의 조합이며 이미지 없는 질문의 중복도 계속 금지한다.

현재 국기 자산은 [country-flags](https://github.com/hampusborgos/country-flags)의 커밋 `c09927e63705529bbf59ca6684cd9b23225dddad`에서 가져왔다. 해당 프로젝트는 Wikimedia Commons 기반 자료로 안내한다. AI로 생성하지 않았으며 원래 도형·비율은 보존하고 메타데이터·주석·제목을 제거했다. 원본 출처와 개정 연결은 운영자 provenance에 기록한다.

지도는 공개 지리 자료를 바탕으로 범위를 발췌하고 표적을 표시한다. 실제 작품·도면·기호는 이용 조건이 확인된 자료를 사용한다. 축·음표·경기장 도해는 원 출처의 조건을 보존한 교육용 예시임을 출처 메타데이터에 기록한다. 이미지 제공자와 이용 조건은 답 제출 뒤 출처에서 확인할 수 있다. 풀이 화면의 **이미지 크게 보기**는 네이티브 모달로 확대하며, 모바일에서는 확대 영역을 가로로 스크롤할 수 있다. Escape 또는 닫기로 돌아온다.
