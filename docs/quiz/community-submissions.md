# 사용자 문제 제출

로그인한 사용자가 `/submit`에서 문제를 작성하고, 운영자가 출처·정답·상식성을 검수한 뒤 문제 은행에 게시한다. 홈 하단의 ‘문제 제안하기’에서 들어갈 수 있다. 제출·검수 과정은 AI를 호출하지 않는다.

## 사용자 흐름

1. 9개 대분류 중 하나와 그에 속하는 소분류를 선택한다. 기존 49개 소분류 목록을 생성 도구와 공유한다.
2. 예상 난이도, 문제, 서로 다른 보기 4개, 정답 하나, 해설, HTTPS 출처를 입력한다.
3. `pending`으로 저장한다. 문제 은행에 바로 넣거나 출제하지 않는다.
4. 같은 화면의 내 제출 기록에서 최근 30개와 검토 결과를 확인한다. 승인은 `게시 승인`, 반려는 `보완 필요`로 표시한다.
5. 운영자가 승인하면 문제 은행에 게시되며 기존 평가·신고·출제 정책을 적용받는다.

숫자 계산·자격증 시험형 지식·지엽적 암기는 제외한다. 소분류가 좁아도 소재는 일상에서 접할 수 있는 상식으로 잡는다. 전문 지식의 희귀함으로 난도를 높이지 않는다.

## 서버 경계

- `question_submissions`는 `bank_questions`와 별도다. 사용자 신원은 인증 세션에서 얻고 요청의 소유자·게시 상태 필드는 거부한다.
- API는 로그인과 같은 origin의 JSON 요청을 요구한다. 서버에서도 4개 보기, 중복 보기, 정답 범위, 분류, 길이, HTTPS 출처를 검증한다. 출처 주소를 서버가 자동으로 가져오지는 않는다.
- 최근 24시간 동안 계정당 최대 5개다. DB 잠금으로 동시 요청에도 한도를 지키며, 같은 요청 ID와 같은 내용은 다시 저장하지 않는다.
- 제출 조회는 본인 최근 기록만 반환한다. 목록 응답에는 정답·보기·해설과 다른 사용자의 식별자를 포함하지 않는다.
- 운영자 검수는 DB 권한을 가진 CLI에서만 수행한다. 공개 승인 API와 관리자 웹 UI는 없다. 승인 시 새 문제 생성과 상태 변경을 같은 트랜잭션으로 처리한다. 내용 중복·이미 처리된 제출은 거절하며 원래 기록을 보존한다.
- 반려된 문제는 사용자가 출처나 해설 등을 보완해 새 제출로 보낼 수 있다. 검토 중이거나 승인된 같은 질문의 중복 제출은 막는다. 제출 수정 UI는 아직 없으며 운영자는 반려 사유에 필요한 보완점을 적는다.

## 운영자 검수

```sh
npm run submissions -- queue
npm run submissions -- show <제출UUID>
npm run submissions -- approve <제출UUID> <검수자> "출처·정답·보기·상식성 확인"
npm run submissions -- reject <제출UUID> <검수자> "보완할 내용을 구체적으로 안내"
```

`show`는 정답을 포함한다. 출력은 공개하지 않는다. 출처 링크를 실제로 읽고 정답 유일성, 문제의 독립성, 난이도와 일반 상식 적합성을 확인한 뒤 승인한다. 반려 사유는 작성자에게 보이므로 내부 정보나 개인정보를 쓰지 않는다.

## 현재 범위

AI 생성은 기존 운영자 도구의 `--subcategory`로 계속 수행한다. 예산이 소모되는 사용자용 AI 생성 버튼은 추가하지 않았다. 새 분류를 선택하는 화면은 이번 제출 기능에 적용하며, 메인 풀이 화면은 기존 5개 분야를 유지한다. 기존 문제 76개와 풀이·평가 데이터는 변경하지 않는다.

자동 사실 검증, 작성자 보상·랭킹, 공개 제출 피드, 제출 수정과 관리자 검수 UI는 이후 단계다. 계정당 제한은 다중 계정 악용을 완전히 방지하지 않으며 이메일 인증은 기존 후속 과제로 남는다.

## 검증 (2026-10-07)

단위 테스트 106개, 임시 PostgreSQL 통합 테스트 33개, lint·타입 검사·프로덕션 빌드와 로컬 Docker 시작을 확인했다. 로컬 실제 API에서 비로그인 차단, 가입 후 작성 화면, 제출 격리, 재요청 중복 방지, 다른 계정의 조회 차단, 운영자 CLI 반려·작성자 결과 조회를 검증했다. 임시 계정을 정리했고 기존 문제 은행과 AI 생성 작업 수는 바뀌지 않았다. 브라우저 자동 조작은 사용하지 않았다.
