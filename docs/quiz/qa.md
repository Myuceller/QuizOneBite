# 문제 품질 QA

QA는 문제 생성과 분리된 운영자 작업이다. 앱에서 문제를 풀 때 실행하지 않는다. 현재 Codex 세션에서 필요할 때 검수하므로 별도 OpenAI API 요청을 만들지 않으며, Codex 자체 이용 한도는 적용된다.

## 역할과 게시 경계

| 역할 | 검토 대상 | 권한 |
| --- | --- | --- |
| 사실 검수 `quiz-fact-reviewer` | 저장 정답을 그대로 믿지 않고 독립 풀이, 복수 정답, 해설, 출처, 시점 조건 확인 | 제공된 문제 읽기와 공개 출처 조회 |
| 편집 검수 `quiz-editorial-reviewer` | 상식성, 짧고 평행한 보기, 그럴듯한 오답, 난이도, 같은 사실 중복 | 제공된 문제 읽기 |
| 조정자 | 기계 검사, ID·내용 해시·검수 범위 확인, 의견 충돌 재검토, 결과 저장 | 사용자에게 허가받은 범위의 별도 DB 작업 |

두 검수자는 DB 접속·수정·게시와 API 키 접근을 하지 않는다. 불확실한 사실은 근거 확보 전 보류한다. 생성자와 검수자가 분리되어도 AI 간의 검토이며 사람의 독립 검수는 아니다.

프로젝트 역할 정의는 `.codex/agents/quiz-fact-reviewer.toml`, `.codex/agents/quiz-editorial-reviewer.toml`에 있다. 모델을 고정하지 않아 부모 세션의 선택을 따른다. TOML 형식은 [공식 하위 에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 기준으로 작성했다. 현재 실행 환경에서 새 역할이 목록에 없으면 동일 지침을 기존 에이전트에 전달해 실행하고, 맞춤 역할이 실제 로드되었다고 표현하지 않는다.

## 실행 방법

Codex에 **“quizquiz-qa로 새 문제 검수해줘”** 또는 **“게시 문제 전체 QA해줘”**라고 요청한다. 절차는 [프로젝트 QA 스킬](../../.agents/skills/quizquiz-qa/SKILL.md)에 있다. 자동 예약이나 유료 API 기반 상시 실행은 설정하지 않았다.

1. 대상 환경과 범위를 명시하고 문제 은행만 읽기 전용으로 스냅샷한다. 원본·정답·개별 보고서는 Git에서 제외된 `.local/quiz-generation/qa-YYYY-MM-DD/`에 저장한다. 회원·비밀번호·플레이 기록은 검수 입력에 포함하지 않는다.
2. 보기 수·중복·정답 인덱스·분류·같은 질문의 중복을 기계 검사한다. 글자 수 초과는 경고 신호이며 자동 탈락 사유가 아니다.
3. 원칙적으로 같은 입력을 사실·편집 두 역할이 검토한다. 대량 재검수에서는 분할된 각 묶음에 두 관점을 적용할 수 있으나 **같은 문제에 대한 두 독립 검수자의 교차 검증과는 구분**해 기록한다. 다른 묶음 사이의 중복은 조정자가 별도로 확인한다.
4. 조정자는 전체 ID가 한 번씩 처리되었는지, 내용 해시가 일치하는지 확인한다. 일부만 읽었다면 부분 검수로 기록한다.
5. 문제가 발견되면 조정자가 근거를 재확인한다. QA 자체는 상태를 바꾸지 않는다. 별도 동기화 요청에서는 미해결 blocker를 새 게시 대상에서 제외한다. 기존 게시 문제를 수정할 때는 [버전 관리](bank.md#데이터와-안전한-채점)를 따른다.

## 판정과 보고

- `pass`: 해당 검수 범위에서 문제를 발견하지 않음. 사실 검증 완료를 뜻하지 않는다.
- `revise`: 긴 보기·난이도·표현·오답 품질 등 편집 개선 필요.
- `hold`: 오답·복수 정답·정답 없음 또는 결론을 바꿀 수 있는 사실의 불확실성. 새 게시를 보류한다.
- `source_verified`: 출처를 직접 열어 핵심 주장과 정답을 대조함. URL와 확인한 주장을 보존한다.
- `not_independently_verified`: 독립적인 출처 대조를 하지 않음. 기존 출처 URL의 존재만으로 검증 완료로 바꾸지 않는다.
- `contradicted`: 확인한 근거와 충돌함.

문항별 결과에는 `id`, 입력 `hash`, `decision`, `factStatus`, `issues`를 넣는다. 이슈에는 `severity`(`blocker`/`warning`), `code`, `reason`, `suggestion`, `evidence`를 기록한다. 출처 확인만 하고 문제가 없는 경우에도 최상위 `evidence`로 근거를 남긴다. 수정된 내용에는 과거 해시의 판정을 재사용하지 않는다.

공개 작업 기록에는 환경, 전체·검수·출처 대조·보류 수, 문제 유형, 별도 API 호출 수, 미검증 범위를 적는다. 정답과 문제 원문은 포함하지 않는다. 난이도 판정은 편집상 잠정값이며 실제 사용자 정답률로 검증된 값이 아니다.
