# 상식 문제 출제 기준

목표는 일반 성인이 흥미롭게 풀고, 해설을 읽은 뒤 일상·뉴스·교양을 조금 더 이해하는 것이다. 문제 수나 난이도 칸을 채우기 위해 지엽적인 사실을 출제하지 않는다.

## 제외할 문제

- 숫자 계산, 비율·확률 계산, 단위 환산, 공식 대입, DNA 염기 비율·서열 풀이.
- 자격증·전공 시험·업무 매뉴얼처럼 전문 용어, 규격, 법조문 번호, 행정 절차를 외워야 하는 문제.
- 드문 인명·연도·횟수·재료명·전시 참여 이력 등 세부 사항 자체가 정답인 문제.
- 긴 조건을 비교해야 하는 보기, 말장난, 함정, 정답만 눈에 띄는 유치한 오답.

모든 숫자나 고유명사를 금지하는 것은 아니다. 널리 알려진 사건·작품·장소를 이해하는 데 필요한 이름과 숫자는 사용할 수 있다. 단, 유명한 소재에 붙은 희귀한 세부 정보를 묻는 것은 제외한다.

| 난이도 | 기준 | 방향 예시 |
| --- | --- | --- |
| 쉬움 | 널리 접하는 개념·대상 | 유명 도시와 수도 구별 |
| 보통 | 익숙한 현상의 이유·차이 | 빵 반죽이 부푸는 이유 |
| 어려움 | 익숙한 주제의 오해·개념 연결 | 태양과의 거리만으로 계절을 설명할 수 없는 이유 |

## 보기 표현 — 짧게 읽고 고르기

정답·오답 모두 **단어, 이름, 짧은 명사구를 기본**으로 한다. 네 개의 설명 문장을 읽고 비교해야 하는 문제는 최대한 피한다. 직접 작성과 API 생성에 같은 기준을 적용한다.

- 대부분 1~3어절, 가능하면 공백 포함 15자 안팎 이하를 권장한다. 기계적인 글자 수 제한은 아니며 고유명사나 의미 구별에 필요한 표현을 억지로 자르지 않는다.
- 공통 상황과 조건은 질문에 한 번만, 이유와 상세 설명은 해설에 쓴다. 질문이 길어지는 방식으로 문장을 옮기지는 않는다.
- 대상·이름·핵심 개념을 고르게 묻고, 네 보기를 같은 범주의 후보로 구성한다. 문법 형태와 길이를 비슷하게 맞춰 정답만 눈에 띄지 않게 한다.
- `~하기 때문에`, `~할 수 있어서` 같은 설명 문장이나 조건 나열은 지양한다. 짧은 구절로는 의미를 정확히 구별할 수 없는 경우에만 간결한 문장형 보기를 예외로 둔다.
- 짧게 보이려고 낯선 전문 용어·약어를 쓰지 않는다. 짧고 명확한 보기 네 개를 만들기 어렵다면 질문의 초점이나 소재를 바꾼다.

예: **“피아노와 바이올린이 같은 높이의 음을 내도 구별하게 해 주는 성질은?”**

`음색 / 음높이 / 음량 / 음의 길이`

난이도는 읽어야 할 문장의 양으로 높이지 않는다. 이 기준은 새 초안 작성과 검수에 적용하며, 기존 게시 문항의 보기를 자동으로 자르지 않는다. 게시 문항의 실제 수정은 [문제 은행의 버전 관리 절차](bank.md#데이터와-안전한-채점)를 따른다.

## 외형·위치·기호는 이미지로 출제

국기의 모양, 지도상의 위치, 지형의 윤곽, 사물의 생김새, 악보·세탁 기호·그래프처럼 시각 정보가 핵심인 문항은 이미지로 제시하는 것을 우선한다. 긴 위치·색·형태 설명을 읽고 머릿속에서 재구성하게 하지 않는다.

- 나라·바다·강·산맥은 주변 위치를 알 수 있는 지도에 대상 영역을 강조하거나 화살표를 둔다. 작은 해협·국경 지역은 확대도를 사용한다. 두 대상을 묻는 문항은 A·B와 순서를 명시한다.
- 국기와 문양은 실제 국기 자료를, 유물·작품·사물은 해당 대상의 사진이나 검증된 도해를 사용한다. 자료의 출처·이용 조건을 확인하고, 정확성이 필요한 국기·지도는 AI로 생성하지 않는다.
- 기호·악보·도표는 실제 표기와 조건을 보여 주고 그 의미나 관계를 묻는다. 그래프는 축·범례를, 지도는 필요한 방향·주변 맥락을 남긴다.
- 정답 이름은 대상 위 글자·캡션·파일명·대체 설명에 노출하지 않는다. 색만으로 대상을 구분하지 않고 화살표·외곽선·A/B 표시를 함께 사용한다. 대체 설명에는 문제를 풀 수 있는 시각적 조건을 담는다.
- 그림을 추가해 기존 정답이 그대로 읽히거나 다른 지식을 묻게 된다면 질문·보기·난이도를 함께 재검토한다. 역사·원리·제도처럼 글이 적절한 문항은 유지하고 필요한 그림은 해설에 배치한다.

후보 목록 선정과 실제 전환·게시는 구분한다. 자산과 개정된 문항을 함께 검수한 뒤 새 ID로 게시하며 기존 풀이 스냅샷을 보존한다. 이미지 저장·표시 계약은 [문제 은행](bank.md#이미지형-문항)을 따른다.

## 생성과 검수

반복 가능한 검수 역할·실행 절차·판정 기준은 [문제 품질 QA](qa.md)를 따른다. 생성과 QA를 분리하며 QA 보고서만으로 DB 상태를 자동 변경하지 않는다.

1. 소분류를 정하고 위 기준에 맞는 핵심 사실만 출처 자료로 추린다. 세부 수치가 많은 전문 자료를 통째로 넣지 않는다.
2. 소분류를 지정해 직접 작성하거나 `bank:generate`로 초안을 만든다. 직접 작성은 별도 생성 API 없이 진행하고 `bank import`로 초안 저장 후 검수한다. 출처로 뒷받침할 수 없는 내용은 수량을 채우려고 게시하지 않는다.
3. 초안을 읽고 “일반 성인이 접할 만한 주제인가?”, “모르면 해설을 읽을 가치가 있는가?”, “어려움이 희귀한 암기에서 오는가?”를 검토한다.
4. 출처와 정답·해설을 대조하고 오답이 정답이 될 여지가 없는지 확인한다. 보기가 짧고 같은 범주인지, 정답만 길거나 구체적이지 않은지도 검토한다. 같은 사실의 바꿔 쓰기 문항도 제외한다.
5. 통과한 초안만 게시한다. 기존 게시 문항이 부적합하면 `bank pause`로 새 출제를 중단하고 사유를 남긴다. 기존 풀이 스냅샷은 보존한다.

소분류를 채울 때는 게시된 문제를 기준으로 부족분만 생성한다. 2026-10-12 사용자 결정에 따른 확장 목표는 **49개 소분류 각각 쉬움·보통·어려움 20개씩**, 분류된 게시 문제 총 2,940개다. 기존의 소분류당 최소 5개 목표에서 확대했으며, 이미 게시된 적합 문항을 포함한 총 보유량을 뜻한다. 초안 작성·검수 완료·게시 수량은 따로 기록하고, 초안을 저장했다고 게시 목표를 달성한 것으로 표시하지 않는다.

같은 사실을 표현만 바꾼 문제로 수량을 채우지 않는다. 난이도를 높이기 위해 희귀한 지식이나 계산을 추가하지 않고, 여러 일상 소재의 이유·차이·흔한 오해를 고른다. 소분류를 넘나드는 중복도 확인하며, 품질 기준에 맞는 문항이 부족하면 부족 수량과 사유를 남긴다.

프롬프트와 JSON 스키마만으로 사실성과 상식성을 자동 보증하지 않는다. 사용자 평가도 검수의 보조 신호다. 인기나 높은 정답률만으로 이 기준을 대신하지 않는다. 초기 샘플·과거 생성 자료 역시 재게시 전에 이 기준으로 검토해야 한다.
