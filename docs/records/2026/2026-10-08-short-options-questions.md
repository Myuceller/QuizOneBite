# 짧은 보기 문제 25개 추가 — 2026-10-08

## 범위와 결과

메인 화면의 5개 주제에 5개씩, 총 25개를 직접 작성해 **로컬 PostgreSQL**에 추가했다. 49개 소분류 각각에 5개씩 추가하는 작업은 아니다. 각 문항에는 기존 분류 체계의 소분류를 지정했다.

| 플레이 주제 | 추가 | 추가 후 게시 수 |
| --- | ---: | ---: |
| 일반 상식 (`general`) | 5 | 146 |
| 과학 (`science`) | 5 | 37 |
| 역사 (`history`) | 5 | 35 |
| 지리 (`geography`) | 5 | 37 |
| 문화 (`culture`) | 5 | 34 |
| 합계 | 25 | 289 |

DB 전체는 314개이며 게시 289개·중단 25개다. 기존 289개 행은 내용·상태·검수 이력까지 변경하지 않았다. 49개 소분류마다 게시 최소 5개, 5개 플레이 주제 × 3난이도마다 게시 최소 5개를 유지한다. 새 문항의 잠정 난이도는 쉬움 11개·보통 13개·어려움 1개이며, 난이도별 추가 수량을 맞추기 위해 지엽적인 문제를 넣지 않았다.

## 작성·검수

- [짧은 보기 기준](../../quiz/quality.md#보기-표현--짧게-읽고-고르기)을 적용했다. 새 보기 100개 모두 단어·이름·짧은 구절이며 공백 포함 최대 9자, 최대 3어절이다.
- 계산·자격증·전공 시험·희귀한 세부 암기를 제외하고 생활 소재, 유명 작품·장소, 일상 현상과 개념의 차이를 골랐다.
- 질문과 핵심 소재를 기존 문제와 비교하고 정답의 유일성, 오답 범주와 길이, 해설을 검토했다. 출처는 NASA, Kew, UNESCO, 박물관·연주단체·공식 기관, 교육 자료와 사전 등에서 문항별로 확인해 DB `sources`에 저장했다.
- 기존 CLI로 `draft` 가져오기 후, 검토한 25개만 트랜잭션으로 `published` 처리했다. `provenance.provider=codex-editorial`, `promptVersion=editorial.short-options.v1`, `batchId=short-options-2026-10-08`로 구별한다.
- 최초 생성 상태 `verificationStatus=unreviewed`를 보존하고 별도 `editorialReview`에 검토 시각·기준·내용 해시를 남겼다. 이번 검토는 Codex의 출처 대조이며 독립적인 사람의 검수나 실측 난이도 보정은 아니다.

## 검증·비용

25개 모두 스키마, 네 보기의 구별, 정답 인덱스, 소분류 매핑, 짧은 보기 기준, 저장된 전체 콘텐츠를 확인했다. 게시 전후 기존 289개 행과 전체 `generation_jobs` 내역이 동일한지 비교했다.

로컬 앱 HTTP API에서 임시 계정으로 5개 주제 × 10문제, 총 50개를 풀었다. 제출 전 정답·해설·출처 비공개, 보기 섞기 후 정답 매핑, 채점과 완료 점수 모두 통과했다. 무작위 출제에 포함된 새 문제는 4개이며 해당 문항의 해설·출처 반환도 원본과 대조했다. 검증용 계정과 종속 플레이 데이터는 삭제했다.

별도 유료 AI API 호출 **0회**, 추가 API 비용 **0달러**다. 앱 코드·생성 프롬프트 변경이 없는 콘텐츠 작업이므로 앱 전체 빌드 대신 DB 콘텐츠 검증과 실제 플레이 경로를 확인했다.

## 확인 위치·적용 환경

- [로컬 Adminer의 문제 은행](http://127.0.0.1:8080/?pgsql=db&username=quizquiz&db=quizquiz&ns=quizquiz&select=bank_questions)에서 확인할 수 있다. Docker 서비스가 실행 중이어야 하며, `created_at` 내림차순으로 정렬하면 최신 문제를 보기 쉽다. 로그인은 [DB 조회 가이드](../../operations/inspect-db.md)를 따른다.
- 정답이 포함된 원본과 전후 스냅샷은 Git에서 제외한 `.local/quiz-generation/short-options-2026-10-08/`에 보관한다. `import-private.json`, `publish-result.json`, `validation.json`에 각각 원본·게시 결과·플레이 검증 결과가 있다.
- Render 테스트 서버와 운영 서버에는 반영하지 않았다. 원격으로 옮길 때는 해당 DB의 기존 상태를 별도로 확인해야 한다.
