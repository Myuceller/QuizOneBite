## 요청 범위와 결과

메인 화면의 5개 주제마다 쉬움·보통·어려움을 각각 5개씩, 주제당 15개·총 75개를 새로 작성했다. 직전에 추가한 25개를 포함한 기존 문항은 그대로 보존했다. 적용 환경은 **로컬 PostgreSQL**이며 원격 배포 DB는 변경하지 않았다.

## 작성·검수 기준

[출제 품질 기준](../../quiz/quality.md)을 적용했다. 새 보기 300개 모두 1~3어절이고 공백 포함 최대 10자다. 이름·단어·짧은 구절로 답할 수 있도록 질문의 초점을 좁혔으며, 계산·전문 시험·드문 연도나 수치의 암기를 제외했다.

쉬움은 익숙한 대상과 기본 개념, 보통은 용어나 현상의 구별, 어려움은 흔한 오해와 개념 연결을 중심으로 편집했다. 난이도는 편집상 잠정 분류이며 실제 사용자 정답률로 보정한 값은 아니다. 어려움도 읽어야 할 보기의 길이를 늘리는 방식으로 만들지 않았다.

공식 기관·박물관·교육 자료·사전 등 공개 자료와 정답·해설을 대조하고 문항별 `sources`에 저장했다. 기존 문제 전체를 읽고 문장 유사도 후보와 핵심 소재를 비교했다. 단순히 키워드가 같은 것과 같은 사실을 다시 묻는 것을 구별했으며, 오답의 모호함과 정답만 눈에 띄는 표현도 수정했다.

기존 CLI로 `draft` 가져오기 후 검토한 75개를 트랜잭션으로 `published` 처리했다. `provenance.provider=codex-editorial`, `promptVersion=editorial.short-options.v1`, `batchId=balanced-75-2026-10-08`로 추적한다. 최초 `verificationStatus=unreviewed`를 유지하고 별도 `editorialReview`에 검토 시각·기준·내용 해시를 기록했다. Codex의 출처 대조이며 독립적인 사람의 검수는 아니다.

## 검증과 비용

- 새 75개 전체의 스키마, 선택지 구별, 정답 인덱스, 소분류, 보기 길이, 저장 콘텐츠를 검증했다. 15개 주제·난이도 조합마다 추가 5개임을 확인했다.
- 로컬 HTTP API에서 각 조합으로 5개씩 출제해 15게임·75개 답안을 채점했다. 필터 일치, 제출 전 정답·해설·출처 비공개, 보기 섞기와 정답 매핑, 완료 점수가 모두 통과했다.
- 무작위 출제에 포함된 새 문항은 26개이며 해당 문항의 정답 매핑과 해설·출처 반환을 원본과 비교했다. 이는 새 75개 전부를 HTTP로 풀었다는 뜻은 아니다. 저장 콘텐츠 비교는 75개 전부 수행했다.
- 검증용 임시 계정 3개와 종속 플레이 데이터를 정리했다. 전체 `generation_jobs` 내역은 작업 전과 동일하다.
- 별도 유료 AI API 호출 **0회**, 추가 API 비용 **0달러**. 앱 코드 변경 없는 콘텐츠 작업이므로 전체 빌드 대신 실제 DB와 출제·채점 경로를 검증했다.
