# 무한모드 구현·로컬 검증

사용자가 기존 5문제 풀이와 함께 무한모드를 요청했다. 홈에 모드 선택을 추가하고, 같은 세션에서 한 문제씩 계속 풀다가 원하는 시점에 종료하도록 구현했다. 최초 구현 단계에서 로컬 구현·DB 마이그레이션·검증을 완료했다. 아래 검증 결과는 원격 배포 전 로컬 단계의 기록이다. 앞서 완료한 문제 2,600개 원격 게시와는 별도 작업이다.

## 동작

- 기존 `5문제 한 입`을 기본 선택으로 유지하고 `무한모드`를 추가했다. 두 모드 모두 주제·난이도를 선택할 수 있다.
- 무한모드는 답 제출 후 다음 문제를 추가한다. 현재 세션에서 가장 적게 등장한 게시 문항을 우선해 가능한 문항을 모두 만나기 전 반복을 피한다. 모두 만나면 복습으로 계속하며, 후보가 둘 이상이면 가능한 경우 직전 문제의 연속 반복을 피한다.
- 누적 풀이 수·정답 수·정답률을 표시한다. `여기까지 마치기`는 제출한 답까지만 집계하고 미제출 문제를 결과에서 제외한다.
- 새로고침과 기록 화면에서 진행 중인 풀이를 복원한다. 완료 기록과 진행 중 기록을 모드·완료 시각으로 구분한다.
- 누적 점수는 전체 기록에서 계산하고, API 응답과 결과 해설 목록은 최근 20문제로 제한한다. 이전 기록도 DB에 유지한다.
- 한 문제씩 추가할 때도 현재 게시 상태를 확인한다. 후보가 없어지면 안내와 재시도·종료 경로를 제공한다.

## 저장·API

`0008_endless_play.sql`은 기존 세션을 `standard`로 유지하는 모드 열을 추가하고, 문제 위치를 정수로 확장하며 10문제 위치 제한과 세션 내 문항 ID 유일성 제약을 제거한다. 기존 문제·답안·점수는 보존한다. 무한모드에서 은행을 모두 만난 뒤 같은 문항을 다시 내더라도 위치별 스냅샷은 별도로 저장된다.

`/api/play/[id]/next`는 마지막 위치를 받고 `/finish`는 명시적 종료를 처리한다. 두 경로 모두 인증·소유권·Origin·입력 검증·공유 요청 제한을 적용한다. 사용자와 세션 잠금으로 동시 요청을 직렬화하고, 같은 위치의 다음 문제 요청을 다시 보내도 한 문제만 추가한다. 답을 내지 않은 건너뛰기와 종료 후 미제출 답안 변경은 거부한다. 제출 전 정답·해설·출처를 숨기는 기존 규칙을 유지하며 AI 호출은 없다.

## 검증 결과

- `npm run lint`, `npm run typecheck`, `npm run build` 통과.
- 일반 테스트 107개 통과. 신규 경로 인증·Origin·소유자 전달·위치 입력·응답 오류·요청 제한을 포함한다.
- 격리된 임시 PostgreSQL 통합 테스트 37개 통과. 24문제 연속 풀이, 한 순환 내 중복 회피, 복습 재출제, 20문제 응답 상한과 전체 누적 점수, 동시 추가·재요청, 이탈 후 복원, 미제출 상태 종료, 종료 후 변경 차단, 후보 전체 중단 시 처리, 기존 모드 회귀를 포함한다.
- 로컬 DB에 `0008_endless_play.sql` 적용 완료. 기존 문제 은행은 변경하지 않았다.
- 실제 Chrome에서 390px 모바일 모드 선택·풀이 화면과 데스크톱 결과 화면을 확인했다. 키보드 방향키로 보기 선택, 정답·오답 표시, 다음 문제의 제목으로 초점 이동, 6문제 풀이 후 7번째 문제 출제, 새로고침, 기록 화면에서 이어 풀기, 중도 종료 후 6문제 누적 결과 복원을 확인했다. 모바일 가로 넘침은 없었다.
- 테스트용 로컬 계정 1개와 해당 풀이·인증 세션을 정리했다. 뷰포트 설정을 원복했고 결과 자료는 Git 제외 비공개 경로에 저장했다.
- 브라우저 네트워크 지연·오프라인 조작과 OS 모션 감소 설정의 실기기는 이번에 별도 검사하지 않았다. 요청 실패·중복 방지와 기존 모션 감소 CSS는 유지한다.

원격에 기능을 반영하려면 코드와 새 마이그레이션을 함께 배포해야 한다. Render 시작 스크립트는 배포 시 미적용 마이그레이션을 먼저 실행한다.

## 배포 요청

로컬 검증 후 사용자가 “이거도 배포해”라고 승인했다. `develop`에 코드와 `0008_endless_play.sql`을 함께 반영하고, GitHub CI 통과 후 기존 Render 테스트 서비스에 배포한다. 배포 후에는 실제 HTTPS에서 5문제를 넘어 이어지는 출제, 누적 채점, 다음 문제 재요청, 이어 풀기와 종료를 확인하고 임시 계정·풀이 기록을 정리한다. 실제 배포 결과와 점검 자료는 Git 제외 운영 기록에 저장한다.
