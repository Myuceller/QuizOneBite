# 버튼 반응과 UI 애니메이션 확장

## 적용

기존 레이아웃과 버튼 눌림·정답 색 변화에 다음 반응을 추가했다.

- 주제 아이콘·선택 체크의 팝 효과, 난이도 막대 채우기, 선택 요약 전환.
- 보기 번호·선택 체크, 선택 안내, 문항별 진행 상태와 완료 반응.
- 정답 확인 후 작은 축하 효과, 결과 점수 링과 결과 목록의 순차 등장.
- 로그인·로그아웃·미리보기·퀴즈 시작·채점·문제 제출·평가 저장의 대기 표시.
- 입력 필드 포커스, 비밀번호 표시 버튼, 기록 링크·화살표·로고 반응, 오류 신고 펼침, 저장 안내.
- 화면 진입 페이드와 환영 화면의 짧은 등장 효과.

CSS와 기존 React 상태를 사용했고 의존성을 추가하지 않았다. 정답 효과는 서버 응답 이후에만 실행한다. 모션 감소 설정에서는 애니메이션과 전환을 제거하고 정적인 선택·결과·로딩 표시를 유지한다. 키보드 radio와 focus 표시를 유지하며 평가 저장에 중복 클릭 방어를 추가했다.

지속 적용할 규칙은 [UI 인터랙션](../../architecture/ui-interactions.md)에 정리하고 [Next.js 스킬](../../../.agents/skills/quizquiz-nextjs/SKILL.md)에 연결했다. QA 에이전트 스킬과 역할은 앞선 작업에서 설정한 그대로 유지한다.

## 검증과 적용 범위

- Mock 모드 `npm run check`: lint·typecheck·기존 테스트 106개·프로덕션 빌드 통과.
- 로컬 Docker 이미지를 재빌드하고 앱·DB healthcheck 통과. [로컬 앱](http://127.0.0.1:3001)에 적용했다.
- HTTP로 홈·로그인·가입·환영·제출·풀이·기록 화면과 새 CSS 제공을 확인했다. 임시 계정으로 1문제 출제·채점 후 점수 링의 서버 렌더링, 제출 전 해설 비노출, 보기 radio 4개를 확인하고 해당 계정·풀이를 삭제했다.
- 브라우저 직접 조작과 모바일 시각 검증은 수행하지 않았다. CSS 구현과 HTTP 검증을 시각 검증 완료로 표현하지 않는다.
- 별도 AI API 호출과 문제 데이터 수정은 없다. 원격 서비스 배포는 이번 UI 작업에 포함하지 않는다.

## 후속: 입체감과 축하 효과 강화

작은 반응보다 눈에 띄는 움직임을 원한 요청에 맞춰 같은 날 UI를 추가 개선했다.

- 홈에 종이 퀴즈 카드 묶음과 별·완료 스티커를 추가했다. 진입 시 펼쳐지며 정밀 포인터 hover에 카드 각도가 바뀐다. 모바일은 작은 장식으로 줄인다.
- 주요 버튼·보기·주제·난이도에 6px 깊이와 눌림 축소를 적용했다. 선택한 카드는 안으로 눌린 상태를 유지하고, 선택 파동·아이콘 팝·주제별 색상으로 반응한다.
- 선택 요약에 주제 아이콘을 추가하고 바뀔 때 짧게 회전하며 등장하도록 했다. 주요 버튼은 hover·키보드 focus 시 반짝인다.
- 진행 막대와 단계 표시에 입체감을 추가하고, 서버 채점으로 정답을 확인했을 때 보기 팝과 18개 색종이를 표시한다. 풀이 완료에는 배지와 색종이를 표시한다.
- 장식은 접근성 트리와 포인터 입력에서 제외한다. 모션 감소 시 새 효과도 모두 중지한다. 타이머나 새 라이브러리 없이 CSS와 기존 상태로 처리했다.

후속 구현도 Mock 모드 `npm run check`(lint·typecheck·106개 테스트·프로덕션 빌드)를 통과했다. 로컬 Docker 앱을 재빌드했고 앱·DB healthcheck가 통과했다. HTTP로 8회 화면 요청과 CSS 제공, 홈 카드 장식·선택 요약, 제출 전 정답 비노출, 채점 결과 점수·완료 배지·색종이 18개 렌더링을 확인했다. 검증용 임시 계정과 풀이 기록은 삭제했다. 브라우저 시각·터치 조작은 수행하지 않았으며, 원격 배포나 문제 은행 변경은 포함하지 않는다. 유료 AI API 호출은 없다.
